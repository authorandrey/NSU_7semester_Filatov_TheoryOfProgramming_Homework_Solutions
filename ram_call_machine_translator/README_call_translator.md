# Транслятор `call` для RAM

Скрипт `call_translator.py` переводит расширенный RAM-ассемблер с псевдоинструкциями `call` и `ret` в обычную RAM-программу `.tur`.

Соглашение о вызовах соответствует семинару 7:

- `R1` содержит адрес команды, с которой нужно продолжить исполнение после возврата из функции;
- `R2`–`R5` используются для передачи параметров и должны сохранять значения после возврата из функции;
- `R6`–`R10` — volatile-регистры, которые функция может изменять;
- результат функции возвращается в `R0`.

Поскольку обычная RAM поддерживает только прямые переходы, `ret` не превращается в `Jump *1`. Вместо этого скрипт генерирует таблицу возвратов: она сравнивает `R1` с адресами всех точек возврата и выполняет соответствующий прямой `Jump`.

## Запуск

Требуется Python 3.9+; сторонние библиотеки не нужны.

```powershell
python .\call_translator.py .\program.tur_call
```

По умолчанию рядом будет создан `program.tur`. Можно задать путь явно:

```powershell
python .\call_translator.py .\program.tur_call -o .\program.tur
```

Транслятор использует область памяти для стека адресов возврата. По умолчанию он выбирает её выше числовых литералов из исходника с дополнительным запасом. Для явного выбора первой ячейки стека:

```powershell
python .\call_translator.py .\program.tur_call --stack-base 10000
```

`--stack-base N` задаёт первую ячейку стека; ячейка `N-1` используется как указатель стека. Исходная программа не должна использовать эту ячейку указателя и область стека `N, N+1, ...`. Автоматический выбор избегает явных числовых адресов из программы, но не может гарантировать отсутствие конфликта с адресами, вычисляемыми динамически через косвенную адресацию.

## Синтаксис расширения

```asm
call FUNCTION_LABEL
```

Вызывает функцию с указанной меткой. Параметры заранее помещаются в `R2`–`R5`. Результат функции после возврата находится в `R0`.

```asm
ret
```

Возвращает управление в точку после соответствующего `call`. Допускается синоним `return`.

Остальные команды и метки — обычный RAM-ассемблер. Комментарии начинаются с `;`. В командах `Jump`, `JZero` и `JGTZ` можно использовать метки или числовые адреса исходной программы. Скрипт перепривязывает числовые переходы к исходным инструкциям даже после раскрытия псевдоинструкций.

## Во что раскрывается `call`

Для каждой точки вызова скрипт генерирует последовательность эквивалентную следующей (адрес возврата здесь обозначен `RET_PC`):

```asm
; Сохранить R1 текущего вызывающего кода на стеке.
Load 1
Store *SP_CELL
Load SP_CELL
Add =1
Store SP_CELL

; Передать функции адрес продолжения.
Load =RET_PC
Store 1
Jump FUNCTION_LABEL

AFTER_CALL: Store 10     ; сохранить результат R0 в volatile-регистре
Load SP_CELL
Sub =1
Store SP_CELL
Load *SP_CELL            ; достать старое значение R1
Store 1
Load 10                  ; восстановить результат функции в R0
```

`SP_CELL` — числовой адрес ячейки указателя стека, который выбирает транслятор. В итоговом `.tur` все эти обозначения заменяются на конкретные адреса и метки; `RET_PC` — фактический номер RAM-инструкции сразу после вызова функции.

## Пример 1. Вызов функции `DOUBLE`

Входной файл `double.tur_call`:

```asm
Read 2
call DOUBLE
Write 0
Halt 0

DOUBLE: Load 2
Mult =2
ret
```

Вызов `call DOUBLE` будет раскрыт в обычные RAM-команды сохранения `R1`, задания адреса возврата, перехода к `DOUBLE` и восстановления после возврата. Функция получает параметр в `R2`, вычисляет `2*R2` в `R0`, не изменяет `R2` и выполняет `ret`.

Запуск транслятора:

```powershell
python .\call_translator.py .\double.tur_call
```

Если на вход RAM-программе подать `21`, выход будет `42`.

Готовые файлы примера находятся в `examples/double.tur_call` и `examples/double.tur`.

## Пример 2. Рекурсивные вызовы

Скрипт поддерживает рекурсию: перед каждым вызовом прежний `R1` помещается в стек, а после возврата восстанавливается. Поэтому рекурсивный вызов из той же самой команды `call` возвращается в правильный кадр.

Однако транслятор не создаёт автоматически стек локальных переменных функции. Функция сама должна сохранять своё состояние и соблюдать контракт `R2`–`R5`. В примере факториала исходный аргумент `R2` перед рекурсивным вызовом сохраняется в отдельном пользовательском стеке и восстанавливается до `ret`.

Файлы примера: `examples/factorial_recursive.tur_call` и сгенерированный `examples/factorial_recursive.tur`. Для входа `5` программа выводит `120`.

## Замечания

- `ret` должен выполняться только при вызове через `call`.
- Функция, которая использует `R2`–`R5`, обязана восстановить их значения перед `ret`.
- `R6`–`R10` не гарантированно сохраняются. Транслятор использует `R10` для временного сохранения результата во время диспетчеризации возврата.
- Переходы по числовым адресам интерпретируются относительно исходного списка инструкций `.tur_call` (счёт с 1), а после трансляции автоматически перенаправляются на соответствующие инструкции.
- Скрипт выдаёт обычный RAM `.tur`; после трансляции его можно собирать штатным RAM-ассемблером.
