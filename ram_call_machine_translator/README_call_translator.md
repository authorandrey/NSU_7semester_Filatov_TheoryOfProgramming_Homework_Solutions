# Транслятор `call` для RAM

Скрипт `call_translator.py` переводит расширенный RAM-ассемблер с псевдоинструкциями `call` и `ret` в обычную RAM-программу `.asm`.

Соглашение о вызовах соответствует семинару 7:

- `R1` содержит адрес команды, с которой нужно продолжить исполнение после возврата из функции;
- `R2`-`R5` используются для передачи параметров и являются non-volatile: значения, полученные функцией на входе, должны быть восстановлены перед возвратом;
- `R6`-`R10` - volatile-регистры, которые функция может изменять; `R10` также используется транслятором как временный регистр;
- результат функции возвращается в `R0`.

Поскольку обычная RAM поддерживает только прямые переходы, `ret` не превращается в `Jump *1`. Вместо этого скрипт генерирует таблицу возвратов: она сравнивает `R1` с адресами всех точек возврата и выполняет соответствующий прямой `Jump`.

## Запуск

Требуется Python 3.9+; сторонние библиотеки не нужны.

```powershell
python .\call_translator.py .\program.ram_call
```

По умолчанию рядом будет создан `program.asm`. Можно задать путь явно:

```powershell
python .\call_translator.py .\program.ram_call -o .\program.asm
```

Транслятор использует общую область памяти для кадров вызовов и адресов возврата. Для каждого вызова в стек помещается `R1`; при входе в функцию автоматически сохраняются `R2`-`R5`, а перед каждым `ret` они восстанавливаются. По умолчанию транслятор выбирает область выше числовых литералов исходника с дополнительным запасом. Для явного выбора первой ячейки стека:

```powershell
python .\call_translator.py .\program.ram_call --stack-base 10000
```

`--stack-base N` задаёт первую ячейку стека (`N` должен быть не меньше `12`); ячейка `N-1` используется как указатель стека, чтобы не пересекаться с рабочими регистрами `R1`-`R10`. Сам стек содержит адрес возврата и сохранённые значения `R2`-`R5` каждого активного вызова. Исходная программа не должна использовать ячейку указателя и область стека `N, N+1, ...`. Автоматический выбор избегает явных числовых адресов из программы, но не может гарантировать отсутствие конфликта с адресами, вычисляемыми динамически через косвенную адресацию.

## Синтаксис расширения

```asm
call FUNCTION_LABEL
```

Вызывает функцию с указанной меткой. Параметры заранее помещаются в `R2`-`R5`. Результат функции после возврата находится в `R0`.

```asm
ret
```

Возвращает управление в точку после соответствующего `call`. Допускается синоним `return`.

Остальные команды и метки - обычный RAM-ассемблер. Комментарии начинаются с `;`. В командах `Jump`, `JZero` и `JGTZ` можно использовать метки или числовые адреса исходной программы. Скрипт перепривязывает числовые переходы к исходным инструкциям даже после раскрытия псевдоинструкций.

## Как строятся кадры вызовов

Транслятор автоматически реализует сохранение non-volatile-регистров `R2`-`R5` для каждой функции, на метку которой есть хотя бы один `call`. Пользовательский код функции не обязан вручную восстанавливать эти четыре регистра перед `ret`.

Каждый вызов работает следующим образом:

1. Инструкция `call F` помещает текущий `R1` на общий стек, записывает в `R1` адрес продолжения и передаёт управление метке `F`.
2. В начале каждой функции, вызываемой через `call`, сгенерированный пролог помещает значения `R2`, `R3`, `R4`, `R5` на тот же стек.
3. Перед `ret` сгенерированный эпилог сохраняет результат `R0` во временном `R10`, снимает `R5`, `R4`, `R3`, `R2` со стека и восстанавливает результат в `R0`.
4. Таблица возвратов выбирает нужную точку продолжения по `R1`. Код после `call` снимает со стека и восстанавливает старое значение `R1`, сохраняя результат функции в `R0`.

Таким образом, каждый рекурсивный вызов получает свой набор ячеек для `R2`-`R5`, и вложенные вызовы не перезаписывают сохранённые значения внешних кадров.

Важно различать сохранение регистра **на границе вызова** и локальные данные функции. Если рекурсивная функция намеренно меняет `R2` с `n` на `n-1` перед `call F`, то после вложенного вызова в `R2` останется значение, бывшее в нём непосредственно перед этим вложенным вызовом, то есть `n-1`. При выходе из внешнего вызова автоматически восстановится входное значение `n`. Если самой функции нужно использовать `n` после подготовки аргумента `n-1`, она всё равно должна сохранить `n` как локальную переменную (например, в пользовательском стеке или отдельной ячейке кадра).

Схематически сгенерированные фрагменты выглядят так:

```asm
; call F: сохранить R1
Load 1
Store *SP_CELL
Load SP_CELL
Add =1
Store SP_CELL
Load =RETURN_PC
Store 1
Jump F

; автоматически в начале F: сохранить non-volatile регистры
Load 2
Store *SP_CELL
Load SP_CELL
Add =1
Store SP_CELL
; аналогично для R3, R4 и R5

; автоматически перед ret: восстановить R2-R5 и сохранить результат R0
Store 10
; снять R5, R4, R3 и R2 со стека и записать их в соответствующие регистры
Load 10
Jump RETURN_DISPATCH
```

`SP_CELL` - числовой адрес ячейки указателя стека, который выбирает транслятор. `RETURN_PC` подставляется как фактический адрес после `call`. В итоговом `.asm` все псевдоинструкции заменены обычными командами RAM.

## Пример 1. Вызов функции `DOUBLE`

Входной файл `double.ram_call`:

```asm
Read 2
call DOUBLE
Write 0
Halt 0

DOUBLE: Load 2
Mult =2
ret
```

Вызов `call DOUBLE` будет раскрыт в обычные RAM-команды сохранения `R1`, задания адреса возврата, перехода к `DOUBLE` и восстановления после возврата. Функция получает параметр в `R2`, вычисляет `2*R2` в `R0`, не изменяет `R2` и выполняет `ret`.

Запуск транслятора:

```powershell
python .\call_translator.py .\double.ram_call
```

Если на вход RAM-программе подать `21`, выход будет `42`.

## Пример 2. Рекурсивные вызовы

Скрипт поддерживает рекурсию: каждый вызов помещает адрес возврата в стек, а каждый вход в функцию сохраняет её входные `R2`-`R5` в отдельном кадре. Поэтому рекурсивный вызов из той же самой команды `call` получает независимый набор сохранённых значений. Перед `ret` значения восстанавливаются автоматически.

Пример рекурсивной функции, которая возвращает исходное число `n`, вычисляя его через базовый случай `0`:

```asm
Read 2
call COUNT
Write 0
Halt 0

COUNT:
Load 2
JZero BASE
Load 2
Sub =1
Store 2
call COUNT
Add =1
ret

BASE:
Load =0
ret
```

Например, для входа `4` функция возвращает `4`. При каждом рекурсивном вызове `R2` меняется на `n-1`, а каждый экземпляр `COUNT` автоматически восстанавливает значения `R2`-`R5`, полученные при собственном входе, перед возвратом.

Транслятор не создаёт автоматически имена локальных переменных и не сохраняет значения, которые функция должна использовать после того, как сама перезаписала их до рекурсивного вызова. Такие локальные данные по-прежнему нужно хранить в пользовательском стеке или отдельных ячейках. Например, для вычисления факториала функция должна сохранить `n` локально, передать `n-1` в `R2`, рекурсивно вызвать себя, а после возврата использовать сохранённое `n` для умножения на рекурсивный результат.

## Замечания

- `ret` должен выполняться только при вызове через `call`; входить в функцию через обычный `Jump` нельзя, если затем она выполняет `ret`.
- Транслятор автоматически сохраняет и восстанавливает `R2`-`R5` для меток, являющихся целью `call`. Это сохраняет значения на границах вызовов, но не заменяет локальные переменные: если функция перезаписала регистр перед вложенным вызовом и ей нужно прежнее значение после возврата, она должна сохранить его отдельно.
- `R6`-`R10` не гарантированно сохраняются. Транслятор использует `R10` для временного сохранения результата в эпилоге и во время диспетчеризации возврата.
- Переходы по числовым адресам интерпретируются относительно исходного списка инструкций `.ram_call` (счёт с 1), а после трансляции автоматически перенаправляются на соответствующие инструкции.
- Скрипт выдаёт обычный RAM `.asm`; после трансляции его можно собирать штатным RAM-ассемблером.
