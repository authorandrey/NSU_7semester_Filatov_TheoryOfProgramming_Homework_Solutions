# Решатель по конечным автоматам

Локальное веб-приложение на React + TypeScript + Vite + Cytoscape.js. Оно показывает граф автоматов, позволяет редактировать их таблицей/текстом/JSON и проигрывать алгоритмы шаг за шагом. Основной акцент — на объяснимых шагах: подсветке состояний и переходов, облачках классов эквивалентности, таблицах и экспорте последовательного решения в PDF.

## Требования

- Node.js 20 или новее (проверялось с Node.js 22).
- npm.
- Браузер с поддержкой Canvas и localStorage.

После установки npm-зависимостей приложение работает локально; внешние API не используются.

## Установка и запуск

Из папки проекта:

```bash
npm install
npm run dev
```

Откройте адрес, показанный Vite (по умолчанию `http://localhost:5173`). Для production-сборки и локального предпросмотра:

```bash
npm run build
npm run preview
```

## Тесты

```bash
npm test
```

Тесты проверяют алгоритмы и математические свойства результата: сохранение языка после минимизации и детерминизации, языки произведений, эквивалентность, различающее слово и обработку неполных автоматов.

## Как пользоваться

1. В левой панели выберите автомат A или B.
2. Измените автомат во вкладке **Таблица**, **Текст** или **JSON**. Удобнее всего ввести автомат таблицей переходов; для НКА в одной ячейке укажите несколько целей через запятую.
3. Для добавления состояния используйте кнопку `+ состояние` или дважды щёлкните по свободному месту графа. Двойной щелчок по состоянию переключает его заключительность. Перетаскивание меняет расположение состояния.
4. Выберите алгоритм в правой панели. Для симуляции укажите слово; для произведения/эквивалентности заполните оба автомата.
5. Нажмите **Запустить**. Используйте кнопки навигации для просмотра всех промежуточных шагов, таблиц и выделенных классов.
6. Краткий PDF содержит ключевые шаги; подробный PDF — все шаги. SVG/PNG экспортируют текущий граф и подсветку; JSON сохраняет оба автомата и трассу.
7. **Импорт JSON** восстанавливает проект, ранее сохранённый кнопкой JSON.

## Текстовый формат автомата

Символы алфавита в этой версии — одиночные символы. `eps`/`ε`/`epsilon` в поле символа перехода означает ε-переход.

```text
states: q0 q1 q2
alphabet: a b
initial: q0
final: q2
transitions:
q0 a q1
q1 b q2
q2 a q2
q0 eps q2
```

Строки, начинающиеся с `//`, считаются комментариями. Имена состояний не должны совпадать со служебными именами визуализатора `__start` и `__g_*`.

## Алгоритмы

- Симуляция ДКА, НКА и ε-НКА.
- Минимизация ДКА алгоритмом Хопкрофта с поиском достижимых состояний и видимым дополнением неполного автомата.
- Табличный метод различимости как дополнительный алгоритм.
- Произведение двух ДКА для пересечения, объединения и симметрической разности.
- Проверка эквивалентности через симметрическую разность и поиск кратчайшего различающего слова.
- Проверка эквивалентности алгоритмом Union-Find с показом классов объединения.
- Детерминизация НКА/ε-НКА методом подмножеств с ε-замыканием и пустым стоковым подмножеством.

Для произведения и проверки эквивалентности автоматы приводятся к общему алфавиту. Отсутствующие переходы трактуются как отказ и переводятся в явно созданное незаключительное стоковое состояние. Алгоритмы, которым нужен ДКА, сообщают об ошибке при подаче НКА.

## Экспорт

- **PDF кратко** — ключевые шаги, которые помечены алгоритмом.
- **PDF все шаги** — полная история вычислений. Для гарантированного отображения кириллицы содержимое страниц растеризуется браузерным Canvas в изображение высокого разрешения.
- **SVG** — текущая диаграмма, включая классы эквивалентности в виде облачков, если они есть на текущем шаге.
- **PNG** — изображение текущего графа.
- **JSON** — сохраняет автоматы, текущий шаг и историю алгоритма; этот JSON можно импортировать обратно.

## Известные ограничения

- Табличный метод различимости помечен как дополнительный: в приложенных материалах курса он упоминался, но не был полноценно изложен в доступном семинарском листе.
- При выключенном дополнении стоковым состоянием минимизация корректно отказывается обрабатывать неполный ДКА вместо выдачи потенциально неправильного ответа.
- Визуальная раскладка больших графов автоматически вычисляется; для печати сложный граф может потребовать ручного перемещения состояний и экспорта SVG/PNG отдельно.
- PDF — растровый, поэтому текст в нём визуально читается, но не выделяется как обычный текстовый слой.
- NFA и ε-NFA поддерживаются в симуляции и детерминизации. Произведение и проверка эквивалентности рассчитаны на ДКА.
