# Решения домашних заданий по теории программирования

Репозиторий содержит решения домашних заданий и вспомогательные инструменты для курса теории программирования — семинаров Филатова.

Основная часть заданий посвящена машинам Тьюринга, машинам RAM/RASP, анализу сложности алгоритмов и реализации классических алгоритмов на ассемблере RAM. Дополнительно в репозитории находятся генераторы программ и тестов, два транслятора расширенного RAM-ассемблера и интерактивное веб-приложение для работы с конечными автоматами.

Задания по машинам Тьюринга основаны на [сборнике задач Theory of Programming Notes](https://github.com/Svazars/theory-of-programming-notes/blob/main/pdfs/problems.pdf).

## 1. Обзор репозитория

Репозиторий состоит из нескольких самостоятельных частей.

| Каталог | Назначение |
|---|---|
| `homework/` | Решения основных домашних заданий: программы, тесты, генераторы и материалы с анализом сложности |
| `extra/` | Дополнительные задачи на машины Тьюринга, шаблоны, генераторы программ и тестов |
| `rasp-machine-emulator/` | Исходный код эмулятора RAM/RASP на Scala, тесты эмулятора и примеры программ |
| `ram_stack_machine_translator/` | Транслятор псевдоинструкций `push` и `pop` в обычные инструкции RAM |
| `ram_call_machine_translator/` | Транслятор псевдоинструкций `call` и `ret` в обычные инструкции RAM |
| `automata-solver/` | Локальное веб-приложение для редактирования, визуализации и пошагового анализа конечных автоматов |
| `notes/` | Дополнительные примеры к семинарам 6 и 7 |

В репозитории используются два независимых средства исполнения программ:

1. **Эмулятор машин Тьюринга** — внешний Java JAR, который используется для запуска `.tur`-программ и их `.test`-тестов.
2. **Эмулятор RAM/RASP** — собственный проект в `rasp-machine-emulator/`, который компилирует `.asm` в `.bin`, исполняет программы и проверяет тесты.

Это разные инструменты. У них разные форматы программ и командная строка.

### Основные типы заданий

- Одноленточные и многоленточные машины Тьюринга.
- Генерация машин Тьюринга для параметризованных задач.
- Преобразование чисел между системами счисления, сложение и умножение.
- Распознавание языков и поиск подстрок.
- Программы RAM для обработки числовых последовательностей, сортировки и вычислений.
- Программирование RAM с косвенной адресацией, стеком и подпрограммами.
- Работа с RASP, где машинный код и данные находятся в общей памяти.
- Минимизация, детерминизация, симуляция и проверка эквивалентности конечных автоматов.

## 2. Требования и подготовка окружения

Для работы со всеми частями репозитория понадобятся разные инструменты. Устанавливать их все необязательно: набор требований зависит от конкретного задания.

| Инструмент | Для чего нужен |
|---|---|
| Python | Генераторы машин Тьюринга, генераторы тестов и трансляторы RAM |
| Java | Внешний эмулятор машин Тьюринга и эмулятор RAM/RASP |
| PowerShell | Удобный запуск файлов `.ps1` в Windows |
| JDK и sbt | Сборка исходного кода `rasp-machine-emulator/` |
| Node.js 20+ и npm | Разработка и запуск `automata-solver/` |
| Современный браузер | Работа с веб-приложением конечных автоматов |

Для совместимости со всеми Python-генераторами рекомендуется использовать Python 3.10 или новее. Для транслятора `call_translator.py` отдельно указано требование Python 3.9+.

### 2.1. Получение репозитория

```bash
git clone https://github.com/authorandrey/NSU_7semester_Filatov_TheoryOfProgramming_Homework_Solutions.git
cd NSU_7semester_Filatov_TheoryOfProgramming_Homework_Solutions
```

### 2.2. Эмулятор машин Тьюринга

Внешний эмулятор используется для файлов `.tur` и тестов `.test`.

Проект и нужный релиз доступны здесь:

- [Репозиторий эмулятора машин Тьюринга](https://github.com/Svazars/turing-machine-emulator)
- [Релиз v0.1.0](https://github.com/Svazars/turing-machine-emulator/releases/tag/v0.1.0)

Скачайте JAR из релиза и положите файл в корень данного репозитория под именем:

```text
turing-machine-emulator.jar
```

Этот файл не хранится в репозитории. Команды тестирования ниже предполагают, что JAR уже скачан и находится именно в корне.

Проверить, доступна ли Java, можно командой:

```bash
java -version
```

### 2.3. Эмулятор RAM/RASP

Для сборки собственного эмулятора нужны JDK и sbt.

На Windows, если установлен Chocolatey:

```powershell
choco install sbt -y
```

Проверка установки:

```powershell
java -version
sbt --version
```

Сборка проекта выполняется в `rasp-machine-emulator/`; подробные команды приведены в разделе [6. Эмулятор RAM/RASP](#6-эмулятор-ramrasp).

### 2.4. Веб-приложение конечных автоматов

Для `automata-solver/` необходимы Node.js 20 или новее и npm. Установка зависимостей, запуск и сборка описаны в разделе [9. Веб-приложение `automata-solver`](#9-веб-приложение-automata-solver).

### 3.2. Запуск обычной программы и тестов

Например, для задания 1.2:

```powershell
cd .\homework\1.2
java -jar ..\..\turing-machine-emulator.jar --program .\1.2.tur --test .\1.2.test
```

Для другого задания замените имя программы и тестового файла.

Скрипт тестирования запускает проверку по всему набору тестов из указанного `.test`. Результат зависит от реализации машины и её соответствия ожидаемым содержимым ленты.

### 3.3. Генерация решения для задания 1.4

В каталоге `homework/1.4/` находятся:

В репозитории также предусмотрен готовый сценарий:

```powershell
.\1.4.GenerateAndRunTests.ps1
```

### 4.2. Задание 2.3: сложение в системе счисления с основанием k

Сценарий использует уже сохранённые в каталоге файлы `2.3_k_is_5.tur`, `2.3_k_is_6.tur`, `2.3_k_is_7.tur` и соответствующие тесты.

### 4.3. Задание 2.4: умножение в системе счисления с основанием k

Каталог `homework/2.4/` содержит:

- `2.4_generator.py` — генератор четырёхленточной машины;
- `2.4_test_generator.py` — генератор тестов;
- `2.4_template.txt` — описание шаблона;
- готовый вариант решения и тесты для основания k = 5;
- `run_tests.ps1` — проверка готового варианта.

Машина умножает два числа. Оба операнда записаны младшим разрядом слева. Первые две ленты сохраняют исходные числа, третья лента предназначена для произведения, а четвёртая используется как временная копия второго операнда. Перед завершением временная лента очищается.

Поддерживаются основания от 2 до 16; цифры со значениями 10–15 обозначаются буквами `A`–`F`.

Генерация программы для основания 5:

Скрипт запускает `2.4_k_is_5.tur` и `2.4_k_is_5.test`. Для других параметров используйте соответствующие файлы, созданные генераторами.

## 5. Дополнительные генераторы в `extra/`

Каталог `extra/` объединяет генераторы машин Тьюринга для дополнительных задач. В каждом подпроекте находятся генератор программы, генератор тестов и, как правило, шаблон `.txt` и/или файл с псевдокодом.

| Каталог | Назначение | Параметры генератора |
|---|---|---|
| `extra/k_m_number/` | Перевод числа из системы с основанием k в систему с основанием m на трёхленточной машине | `k`, `m` |
| `extra/substring_search/` | Поиск заданной подстроки над алфавитом `{a,b}` | `pattern` |
| `extra/db_substring/` | Проверка, является ли входное слово подстрокой фиксированной строки БД | `db` |
| `extra/erase_prefix_before_match/` | Стереть префикс до самого левого вхождения шаблона; при отсутствии совпадения стереть всё слово | `pattern` |
| `extra/add_constant/` | Прибавление константы к числу в системе с основанием m на одноленточной машине | `m`, `k`, `left` или `right` |
| `extra/add_number/` | Сложение двух чисел в системе с основанием k на трёхленточной машине | `k` |
| `extra/reverse_string/` | Разворот слова на одноленточной машине над заданным конечным алфавитом | `alphabet` |
| `extra/validate_number/` | Проверка канонической записи числа в системе с основанием m | `m`, `left` или `right` |

### 5.1. Параметры записи чисел

Для генераторов числовых задач поддерживаются основания от 2 до 36 там, где это указано в конкретном скрипте. Цифры со значениями 10–35 обозначаются символами `A`–`Z`.

Для параметров ориентации:

- `left` означает, что младший разряд числа находится слева;
- `right` означает, что младший разряд числа находится справа.

Допустимые основания и ограничения для каждого генератора проверяются самим скриптом.

### 5.2. Ручной запуск генераторов

Все команды ниже выполняются из каталога соответствующего подпроекта. Имя выходного файла можно передать последним аргументом; без него используется имя по умолчанию.

**Перевод числа между системами счисления:**

```powershell
cd .\extra\k_m_number
py .\k_m_number_generator.py 3 11
py .\k_m_number_test_generator.py 3 11
java -jar ..\..\turing-machine-emulator.jar --program .\k_m_number.tur --test .\k_m_number.test
```

**Поиск подстроки:**

```powershell
cd .\extra\substring_search
py .\substring_search_generator.py aababab
py .\substring_search_test_generator.py aababab
java -jar ..\..\turing-machine-emulator.jar --program .\substring_search.tur --test .\substring_search.test
```

Если подстрока найдена, машина стирает символы до самого левого вхождения, восстанавливает само вхождение и сохраняет суффикс. Если совпадения нет, входное слово стирается целиком.

**Проверка подстроки фиксированной строки БД:**

```powershell
cd .\extra\db_substring
py .\db_substring_generator.py aababab
py .\db_substring_test_generator.py aababab
java -jar ..\..\turing-machine-emulator.jar --program .\db_substring.tur --test .\db_substring.test
```

**Стирание префикса перед совпадением:**

```powershell
cd .\extra\erase_prefix_before_match
py .\erase_prefix_before_match_generator.py aababab
py .\erase_prefix_before_match_test_generator.py aababab
java -jar ..\..\turing-machine-emulator.jar --program .\erase_prefix_before_match.tur --test .\erase_prefix_before_match.test
```

Шаблон должен быть непустым словом над `{a,b}`.

**Прибавление константы:**

```powershell
cd .\extra\add_constant
py .\add_constant_generator.py 10 42 right
py .\add_constant_test_generator.py 10 42 right
java -jar ..\..\turing-machine-emulator.jar --program .\add_constant.tur --test .\add_constant.test
```

В этом примере к числу в десятичной системе прибавляется 42. Параметр `right` задаёт расположение младшего разряда справа.

**Сложение двух чисел:**

```powershell
cd .\extra\add_number
py .\add_number_generator.py 10
```

## 6. Эмулятор RAM/RASP

Каталог `rasp-machine-emulator/` содержит реализацию эмулятора RAM и RASP на Scala.

В отличие от внешнего эмулятора машин Тьюринга, этот проект входит в репозиторий и может быть собран локально.

### 6.1. Структура проекта

### 6.2. Сборка

Из корня репозитория:

```powershell
cd .\rasp-machine-emulator

```

После успешной сборки JAR должен появиться по пути:

```text
target\scala-2.13\rasp-machine-emulator-assembly-0.1.0-SNAPSHOT.jar
```

Чтобы удобно запускать программы из каталогов заданий, скопируйте его в корень репозитория. Команда выполняется после возврата из `rasp-machine-emulator/`:

```powershell

```

В дальнейшем команды предполагают, что `rasp-machine-emulator.jar` находится в корне репозитория.

### 6.3. Основные команды эмулятора

У эмулятора есть несколько режимов:

| Команда | Назначение |
|---|---|
| `java -jar rasp-machine-emulator.jar program.asm` | Скомпилировать RAM-ассемблер в `.bin` |
| `java -jar rasp-machine-emulator.jar program.bin "1 2 3" 1000` | Исполнить программу RAM с заданным входом |
| `java -jar rasp-machine-emulator.jar --test program.bin program.tests 1000` | Проверить RAM-программу по набору тестов |
| `java -jar rasp-machine-emulator.jar --compile-rasp program.asm` | Скомпилировать исходник в формате RASP |
| `java -jar rasp-machine-emulator.jar --rasp program.bin "1 2 3" 1000` | Исполнить программу RASP |
| `java -jar rasp-machine-emulator.jar --rasp-test program.bin program.tests 1000` | Проверить программу RASP по тестам |

Последний числовой аргумент задаёт максимальное число итераций исполнения. Если лимит превышен, эмулятор останавливает вычисление.

Например, сборка и запуск задания 3.1.1:

```powershell
java -jar .\rasp-machine-emulator.jar .\homework\3.1.1\3.1.1.asm
java -jar .\rasp-machine-emulator.jar .\homework\3.1.1\3.1.1.bin "1 10 2" 1000
```

Для проверки готового тестового набора RAM:

```powershell
java -jar .\rasp-machine-emulator.jar --test .\homework\3.1.1\3.1.1.bin .\homework\3.1.1\3.1.1.tests 1000
```

Входные числа передаются одной строкой через пробел. Программа читает их командами `Read`, а выведенные значения формируются командами `Write`.

### 6.4. Чем отличаются RAM и RASP

В обычной RAM программа и данные логически разделены. В RASP машинный код размещается в той же памяти, что и данные. Это влияет на адреса команд и переходов.

Поэтому RASP-программы требуется компилировать и запускать в соответствующем режиме:

```powershell
java -jar .\rasp-machine-emulator.jar --compile-rasp .\homework\4.2\4.2.asm
java -jar .\rasp-machine-emulator.jar --rasp .\homework\4.2\4.2.bin "0" 1000
```

**Не смешивайте режимы:** для `.bin`, полученного через `--compile-rasp`, используется `--rasp` или `--rasp-test`. Для обычной RAM-программы используются команды без префикса `--rasp`.

### 6.5. Поддерживаемые команды RAM/RASP

В исполнитель встроены команды:

- `Load`, `Store`;
- `Add`, `Sub`, `Mult`, `Div`;
- `Read`, `Write`;
- `Jump`, `JZero`, `JGTZ`;
- `Halt`.

Для работы с аргументами используются режимы адресации, в частности непосредственная константа с `=` и косвенная адресация с `*`.

Примеры:

```asm
Load =10   ; загрузить константу 10
Load 1     ; загрузить значение из регистра 1
Load *1    ; косвенная адресация через содержимое регистра 1
Store 2    ; записать аккумулятор в регистр 2
Jump LOOP  ; переход по метке
```

Точное поведение инструкций и адресации определяется реализацией в `Common.scala`, `Executor.scala` и парсере ассемблера.

## 8. Трансляторы расширенного RAM-ассемблера

В репозитории есть два независимых транслятора, каждый из которых расширяет язык ассемблера RAM псевдоинструкциями. Они генерируют обычный `.asm`, который затем можно компилировать штатным эмулятором RAM.

### 8.1. Транслятор стека: `ram_stack_machine_translator/`

Файл:

```text
ram_stack_machine_translator/ram_stack_translator.py
```

Назначение: заменить псевдоинструкции `push` и `pop` обычными командами RAM с использованием выделенной области памяти.

Поддерживаемые формы:

```asm
push OPERAND
pop DEST
```

Для `push` поддерживаются непосредственная константа, прямая и косвенная адресация операнда. Для `pop` — прямая и косвенная адресация назначения.

По умолчанию исходный файл `program.ram_stack` преобразуется в `program.asm` рядом с ним.

Примеры запуска:

```powershell
py .\ram_stack_machine_translator\ram_stack_translator.py .\notes\seminar_6\stack_realization\stack_realization.ram_stack
```

Выходной файл можно указать явно:

```powershell
py .\ram_stack_machine_translator\ram_stack_translator.py .\notes\seminar_6\stack_realization\stack_realization.ram_stack -o .\notes\seminar_6\stack_realization\stack_realization.asm
```

Можно задать адрес первой ячейки стека:

```powershell
py .\ram_stack_machine_translator\ram_stack_translator.py .\notes\seminar_6\stack_realization\stack_realization.ram_stack --stack-base 10000
```

#### Организация памяти стека

- `B` — адрес первой ячейки стека.
- Указатель стека расположен в `M[B-1]`.
- Указатель хранит адрес следующей свободной ячейки.
- Стек растёт к большим адресам.
- Ячейка `B-1` и ячейки от `B` вверх зарезервированы под стек.

Если адрес стека не указан, транслятор выбирает его автоматически на основе числовых литералов исходной программы. Это эвристика, а не гарантия отсутствия пересечения с областями памяти, к которым программа обращается динамически. При использовании косвенной адресации корректность размещения стека нужно проверять отдельно.

#### Пример использования

Для демонстрационной программы из `notes/seminar_6/stack_realization/`:

```powershell
cd .\notes\seminar_6\stack_realization
py ..\..\..\ram_stack_machine_translator\ram_stack_translator.py .\stack_realization.ram_stack --stack-base 4
java -jar ..\..\..\rasp-machine-emulator.jar .\stack_realization.asm
java -jar ..\..\..\rasp-machine-emulator.jar .\stack_realization.bin "1 2 3 0" 1000
```

Входные числа читаются до нуля, после чего программа выводит ненулевые числа в обратном порядке.

### 8.2. Транслятор подпрограмм: `ram_call_machine_translator/`

Файл:

```text
ram_call_machine_translator/call_translator.py
```

Назначение: преобразовать псевдоинструкции `call` и `ret` в обычный RAM-ассемблер.

Используются следующие соглашения:

- `R1` содержит адрес возврата;
- `R2`–`R5` используются для параметров и должны сохранять значения после возврата;
- `R6`–`R10` — временные регистры, которые функция может менять;
- результат функции возвращается в `R0`.

Синтаксис:

```asm
call FUNCTION_LABEL
```

и

```asm
ret
```

Синоним `return` также поддерживается.

Транслятор сохраняет адрес возврата в стеке, передаёт управление функции, а затем восстанавливает адрес возврата и результат. Это позволяет использовать рекурсивные вызовы. Однако он не создаёт автоматический стек локальных переменных: функцию нужно самостоятельно реализовать так, чтобы она соблюдала соглашение о регистрах.

Запуск:

```powershell
py .\ram_call_machine_translator\call_translator.py .\notes\seminar_7\map\map_sum.tur_call
```

Выходной `.asm` можно задать явно:

```powershell
py .\ram_call_machine_translator\call_translator.py .\notes\seminar_7\map\map_sum.tur_call -o .\notes\seminar_7\map\map_sum.asm
```

При необходимости можно указать начало области стека:

```powershell
py .\ram_call_machine_translator\call_translator.py .\notes\seminar_7\map\map_sum.tur_call --stack-base 10000
```

Полученный `.asm` затем компилируется обычным RAM-эмулятором, без режима RASP:

```powershell
java -jar .\rasp-machine-emulator.jar .\notes\seminar_7\map\map_sum.asm
```

Транслятор перепривязывает числовые адреса в `Jump`, `JZero` и `JGTZ` к соответствующим инструкциям после раскрытия псевдоинструкций.

### 8.3. Документация трансляторов

В каталогах трансляторов есть отдельные README:

- `ram_stack_machine_translator/README_stack_translator.md`;
- `ram_call_machine_translator/README_call_translator.md`.

В них приведены соглашения, описание раскрытия псевдоинструкций и подробности работы со стеком.

```bash
npm test
```

Сценарий запускает Vitest. Тесты проверяют алгоритмы и математические свойства результата, в частности сохранение языка при детерминизации и минимизации, операции над языками, эквивалентность, нахождение различающего слова и обработку неполных автоматов.

### 9.4. Как работать с приложением

1. Выберите автомат A или B в левой панели.
2. Измените его через вкладки **Таблица**, **Текст** или **JSON**.
3. Для НКА в одной ячейке таблицы можно указать несколько целевых состояний через запятую.
4. Выберите алгоритм на правой панели. Для симуляции введите слово; для операций над двумя автоматами заполните A и B.
5. Нажмите **Запустить**.
6. Перемещайтесь по истории шагов, чтобы посмотреть изменения автомата, состояния и переходы, таблицы и классы эквивалентности.
7. Экспортируйте результат в нужном формате.

Для добавления состояния можно использовать кнопку `+ состояние` или двойной щелчок по свободному месту графа. Двойной щелчок по состоянию переключает его заключительность. Состояния можно перетаскивать.

### 9.5. Текстовый формат автомата

Пример:

```text
states: q0 q1 q2
alphabet: a b
initial: q0
final: q2
transitions:
q0 a q1
q1 b q2
q2 a q2
q0 eps q2
```

Строки, начинающиеся с `//`, считаются комментариями.

Символы алфавита в текущей версии — одиночные символы. Для ε-перехода используйте `eps`, `ε` или `epsilon`. Имена состояний не должны совпадать со служебными именами визуализатора `__start` и `__g_*`.

### 9.6. Реализованные алгоритмы

| Алгоритм | Возможности |
|---|---|
| Симуляция | ДКА, НКА и ε-НКА |
| Минимизация | Алгоритм Хопкрофта с поиском достижимых состояний и дополнением неполного автомата |
| Табличный метод | Табличный метод различимости пар состояний |
| Произведение | Пересечение, объединение и симметрическая разность двух ДКА |
| Проверка эквивалентности | Через симметрическую разность и поиск кратчайшего различающего слова |
| Union-Find | Проверка эквивалентности с визуализацией операций объединения классов |
| Детерминизация | Метод подмножеств с ε-замыканием и пустым стоковым состоянием |

Для произведения и проверки эквивалентности используются ДКА. НКА и ε-НКА можно симулировать и детерминизировать; соответствующие ограничения проверяются приложением.

### 9.7. Экспорт

Приложение предоставляет несколько вариантов экспорта:

- **PDF кратко** — ключевые шаги, помеченные алгоритмом;
- **PDF все шаги** — полная последовательность вычислений;
- **SVG** — векторная схема текущего графа;
- **PNG** — изображение графа;
- **JSON** — сохранение автоматов, текущего шага и истории алгоритма с возможностью последующего импорта.

PDF формируется растеризацией страниц браузерным Canvas, чтобы сохранить корректное отображение кириллицы. Поэтому PDF визуально читаем, но его текст не является обычным выделяемым текстовым слоем.

## 10. Материалы семинаров

Каталог `notes/` содержит дополнительные программы и примеры, которые не оформлены как самостоятельные папки домашних заданий.

### 10.1. Семинар 6: косвенная адресация

```text
notes/seminar_6/indirect_addressing/
├── inderect_addressing.asm
└── inderect_addressing.bin
```

Программа вычисляет скалярное произведение двух последовательностей:

\[
\sum_{i=1}^{n} a_i b_i.
\]

Вход: `n`, затем элементы первого массива a₁,…,aₙ, затем элементы второго массива b₁,…,bₙ. Программа использует косвенную адресацию, хранит первый массив в памяти и последовательно умножает его элементы на элементы второго массива.

### 10.2. Семинар 6: реализация стека

```text
notes/seminar_6/stack_realization/
├── stack_realization.ram_stack
└── test.ps1
```

`stack_realization.ram_stack` — программа на расширенном RAM-ассемблере с `push` и `pop`. Она читает ненулевые числа до нуля, складывает их в стек, а затем выводит в обратном порядке.

`test.ps1` демонстрирует полный процесс: трансляцию в `.asm`, компиляцию в `.bin` и запуск RAM-программы.

### 10.3. Семинар 7: `MAP` и вызовы функций

```text
notes/seminar_7/map/
├── map_sum.tur_call
└── test.ps1
```

`map_sum.tur_call` — пример использования `call` и `ret`. Программа обрабатывает последовательность кортежей, передавая параметры функции `F` и выводя результат её работы. В примере функция вычисляет сумму параметров.

Файл полезен для изучения соглашения о регистрах, передачи аргументов и организации вызовов подпрограмм с помощью `ram_call_machine_translator/`.

## 11. Форматы файлов

В репозитории используются несколько форматов, предназначенных для разных инструментов.

| Расширение | Назначение |
|---|---|
| `.tur` | Исходный код машины Тьюринга |
| `.test` | Набор тестов для эмулятора машин Тьюринга |
| `.asm` | Исходный RAM/RASP-ассемблер |
| `.bin` | Скомпилированная программа RAM/RASP или другой бинарный артефакт, если это указано в конкретном каталоге |
| `.tests` | Набор тестов для RAM/RASP-эмулятора |
| `.tex` | Исходный документ LaTeX с решением, условием и/или анализом сложности |
| `.pdf` | Готовый документ с решением |
| `.py` | Генератор программ, генератор тестов или транслятор |
| `.ps1` | Сценарий автоматизации для Windows PowerShell |
| `.txt` | Шаблон программы или псевдокод |
| `.ram_stack` | Расширенный RAM-ассемблер с псевдоинструкциями стека |
| `.tur_call` | Расширенный RAM-ассемблер с псевдоинструкциями `call` и `ret` |
| `.scala` | Исходный код эмулятора RAM/RASP |
| `.tsx`, `.ts`, `.css` | Исходный код веб-приложения конечных автоматов |

### Важные различия

- Для `.tur` и `.test` используется внешний `turing-machine-emulator.jar`.
- Для `.asm`, `.bin` и `.tests` в RAM/RASP-заданиях используется `rasp-machine-emulator.jar`.
- `.ram_stack` и `.tur_call` сначала проходят через соответствующий Python-транслятор. Только после преобразования их можно компилировать обычным эмулятором RAM.
- RASP-программы нужно собирать и запускать в режиме RASP, поскольку адреса команд в общей памяти отличаются от адресации обычной RAM.
- Для воспроизводимости экспериментов стоит хранить вместе исходную программу, тесты и генератор, если он использовался.

## 13. Известные особенности и ограничения

1. **Эмулятор машин Тьюринга не включён в репозиторий.** Для запуска `.tur` и `.test` нужно отдельно скачать JAR из указанного релиза и сохранить его в корне под именем `turing-machine-emulator.jar`.

2. **Интерактивный лаунчер `extra_launcher.py` пока охватывает не все папки `extra/`.** В настоящее время он предоставляет меню только для `k_m_number`, `substring_search` и `db_substring`. Остальные генераторы запускаются напрямую командами из раздела 5.

3. **Некоторые README ссылаются на примеры, которых нет в текущем дереве каталогов.** В частности, документация трансляторов упоминает каталоги `examples/`, но в самих каталогах трансляторов сейчас находятся README и исходные скрипты; демонстрационные примеры приведены в `notes/`.

4. **Не для каждого задания сохранён исходник LaTeX.** Например, в `homework/3.1.6c/` есть исходный ассемблер, бинарная программа, тесты и PDF, но отсутствует `3.1.6c.tex`.

5. **Готовые `.bin` не заменяют исходные `.asm`.** Если вы изменили программу, пересоберите её и запустите соответствующие тесты. При изменении RASP-кода используйте `--compile-rasp`, а при исполнении — `--rasp`.

6. **Для стека и подпрограмм нужно контролировать использование памяти.** Автоматический выбор адреса стека основан на анализе числовых литералов. Динамические адреса могут привести к пересечению стека с рабочей областью программы, поэтому для сложных программ рекомендуется задать `--stack-base` явно.

7. **У `automata-solver` есть документированные ограничения.** Табличный метод различимости помечен как дополнительный алгоритм. Произведение и проверка эквивалентности рассчитаны на ДКА; для НКА и ε-НКА доступны симуляция и детерминизация. Визуальная раскладка крупных графов может потребовать ручной настройки перед экспортом. В PDF текст нельзя выделять как обычный текстовый слой, поскольку страницы растеризованы.

8. **Уровень проверки зависит от инструмента.** Для машин Тьюринга проверяйте программу соответствующим эмулятором и тестами. Для RAM/RASP используйте `.tests` и правильный режим исполнения. Для веб-приложения запускайте `npm test` и `npm run build` в окружении с установленными npm-зависимостями.
